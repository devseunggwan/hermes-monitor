# Hermes Monitor

**Kanban 워커 상태와 프로바이더 쿼터를 Hermes Desktop 상태바에서 실시간으로 보여 줍니다.**

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE) [![Hermes](https://img.shields.io/badge/Hermes-%E2%89%A50.21-6f42c1.svg)](#요구-사항)

[English](README.md) | 한국어

![Desktop 하단 상태바의 Hermes Monitor](docs/footer.png)

Kanban 워커는 아무 신호 없이 멈추거나 같은 동작을 반복할 수 있고, 쿼터 창은 작업 도중에 바닥날 수 있습니다. Hermes Monitor 는 이 두 신호를 늘 보는 하단 상태바에 띄워, 실행 하나를 날리기 전에 알아차리게 해 줍니다. 모델을 호출하지 않으며 로컬 상태는 읽기 전용으로만 엽니다.

## 기능

- **워커 상태를 한눈에.** 실행 중인 Kanban 카드 수와 스피너를 가장 나쁜 상태(정상, 멈춤, 반복)의 색으로 보여 줍니다.
- **멈춤·반복 감지.** 멈춤은 Kanban 보드 자체의 heartbeat 기준을 따르고, 반복은 같은 도구를 같은 인자로 거듭 호출하는 경우입니다.
- **풀에 든 모든 계정의 쿼터.** Claude·Codex 사용량 창과 그 밖에 Hermes 가 사용량을 읽을 수 있는 모든 프로바이더를 모든 Hermes 프로필에 걸쳐 모으고, DeepSeek 키 하나의 잔액을 더합니다.
- **페이스(pace).** 균등한 소비 속도보다 앞서 있는지, 지금 속도라면 창이 언제 바닥나는지 보여 줍니다.
- **정직한 수치.** 각 행은 방금 읽은 값인지, 이전 값을 붙잡아 둔 것(`cached`)인지, 기록된 한도로 추정한 것인지 표시합니다. 알 수 없는 값은 `n/a` 입니다.
- **설계부터 읽기 전용.** 쿼터 조회는 자격 증명을 갱신하거나 쓰지 않으며, 메시지 내용과 도구 인자는 UI 에 전달되지 않습니다.

## 요구 사항

- Hermes 0.21 이상
- Hermes Desktop

## 빠른 시작

[**Hermes 에 설치**](hermes://plugin/install?repo=devseunggwan/hermes-monitor)

터미널에서 설치하려면:

```sh
hermes plugins install devseunggwan/hermes-monitor --enable
```

그다음:

1. Hermes Desktop 을 완전히 종료(Command-Q)한 뒤 다시 엽니다.
2. **Capabilities -> Plugins -> Hermes Monitor** 에서 Desktop 쪽 스위치를 켭니다. 새로 설치한 플러그인의 Desktop 쪽은 꺼진 상태로 시작합니다.

하단 상태바 오른쪽에 두 항목이 나타납니다.

> Hermes 플러그인 카탈로그의 `hermes-monitor` 항목은 원본 저장소의 이전 릴리스(0.3.5)를 설치합니다. [CHANGELOG.md](CHANGELOG.md) 의 *Unreleased* 에 적힌 변경은 들어 있지 않습니다.

### 로컬 체크아웃에서 실행

```sh
ln -s "$PWD" ~/.hermes/plugins/hermes-monitor
hermes plugins enable hermes-monitor
```

그다음 Hermes Desktop 을 종료했다가 다시 엽니다. 플러그인 경로는 Desktop 자체의 Hermes 백엔드가 제공하므로, 메시징 게이트웨이를 재시작해도 로드되지 않습니다.

## 사용법

| 상태바 항목 | 표시 내용 | 클릭하면 |
|---|---|---|
| **Workers** | 실행 중인 카드 수와 스피너, 가장 나쁜 상태의 색 | 카드별 제목, 카드 id, 담당자, 실행 시간, 마지막 활동 |
| **Quotas** | 프로바이더별 첫 사용량 창의 막대와 퍼센트(또는 잔액), 계정이 여럿이면 `×N` 배지 | 계정별 모든 창, 리셋 시각, 페이스, 상태 |

메뉴를 열면 새로 읽어 옵니다. Quotas 메뉴 오른쪽 위의 새로고침 버튼은 모든 계정을 한 번에 다시 읽습니다([새로고침과 캐시](#새로고침과-캐시) 참고).

## 동작 방식

### 워커 상태

실행 중인 Kanban 카드마다 그 카드의 워커 세션, 즉 첫 메시지에 카드 이름이 나오는 Kanban 세션을 짝지어 상태를 정합니다.

| 상태 | 의미 |
|---|---|
| 정상(Active) | 최근 워커 활동이 있습니다. 아직 heartbeat 가 없는 카드도 정상으로 봅니다. |
| 멈춤(Stalled) | 카드의 Kanban heartbeat 가 120초보다 오래됐습니다. 보드 자체의 주황 경고 기준과 같습니다. heartbeat 열이 없는 보드에서는 5분 넘게 도구 호출이 없을 때입니다. |
| 반복(Loop) | 최근 이벤트에서 같은 도구가 같은 인자로 4번 이상 연달아 나옵니다. |

상태바는 실행 중인 카드 중 가장 나쁜 상태를 따릅니다. 반복, 멈춤, 정상 순입니다.

### 쿼터

프로바이더 목록은 Hermes 에서 가져옵니다. Hermes 가 계정 사용량을 읽을 수 있는 모든 프로바이더(내장된 Claude·Codex 와 사용량 조회를 제공하는 프로바이더)이고, `DEEPSEEK_API_KEY` 가 있으면 DeepSeek 도 포함합니다. 자격 증명이 없는 프로바이더는 숨기고, 로컬 전용 프로바이더는 건너뜁니다. 조회에 실패한 프로바이더는 `n/a` 로 남습니다.

- **Claude** 는 5시간(`5h`)과 주간(`week`) 창을, **Codex** 는 돌려받은 창(`Session`, `Weekly`)을 보여 줍니다. 창마다 사용 퍼센트와 리셋 시각이 있고, 오늘이 아닌 리셋 시각에는 날짜(`MM/DD HH:MM`)가 붙습니다.
- **DeepSeek** 는 남은 잔액을 보여 줍니다. 키는 프로세스 환경변수, Hermes 루트 `.env`, 그다음 `DEEPSEEK_API_KEY` 가 들어 있는 첫 프로필 `.env`(알파벳 순) 순서로 찾습니다. 읽는 키는 그 하나뿐입니다. DeepSeek 는 풀 프로바이더가 아니므로 다른 프로필의 DeepSeek 키는 표시되지 않습니다.

#### 페이스

5시간 창과 주간 창에는 페이스가 붙습니다. 메뉴의 막대에 창의 경과 비율이 표시되므로, 사용량이 그 표시보다 오른쪽이면 균등한 속도보다 앞서 있는 것입니다. 지금까지의 속도로 리셋 전에 100% 에 닿으면 막대가 주황색으로 바뀌고(상태바에서도), 메뉴에 예상 소진 시각이 나옵니다. 창의 처음 5% 구간, 길이를 모르는 창, 이전 값을 붙잡아 둔 수치에는 페이스를 표시하지 않습니다.

#### 계정

- 모든 Hermes 프로필(기본 프로필과 `profiles/` 아래의 이름 있는 프로필)에서 계정을 모으고, 어느 프로필에서 왔는지 표시합니다.
- 같은 이메일로 로그인한 풀 항목들은 한 행으로 합치고, 몇 개 항목을 대표하는지 적습니다(`· 2 entries`). 프로바이더 머리글과 상태바 배지는 행 수를 셉니다.
- Claude 행은 그 계정이 로그인한 이메일로 이름을 붙이고, 이메일을 모르면 풀 라벨을 씁니다. 그래도 이름이 겹치는 행에는 풀 항목 id 를 덧붙입니다(`<label> · <id>`). 다른 프로바이더는 이메일을 표시하지 않습니다.

#### 계정 상태

| 표시 | 의미 |
|---|---|
| `exhausted` | Hermes 가 쿼터 한도로 계정을 쉬게 했거나(그 리셋 시각을 표시), 어떤 창이 100% 로 읽혔고 아직 리셋되지 않았습니다. |
| `exhausted (estimated)` | 사용량 조회 값이 없어 Hermes 가 기록한 한도 정보로 만든 행입니다. |
| `cached` | 마지막 조회가 실패해 그 계정의 마지막 정상 값을 최대 6시간 보여 줍니다. |
| `n/a` | 모니터가 알 수 없는 값입니다. |

한도에 걸린 Claude·Codex 계정도 5시간 행과 주간 행을 유지합니다. 걸린 쪽 한도는 100% 로, 주간 한도에 걸린 계정의 5시간 행은 쉬기 시작한 뒤 5시간이 지나면 0% 로, 알 수 없는 행은 `n/a` 로 표시합니다. 주간 한도에 걸린 계정은 마지막 조회에 5시간 창이 있었을 때만 5시간 행을 보여 줍니다. 5시간 창이 없는 Claude 요금제도 있기 때문입니다. 다른 프로바이더는 `limit` 행 하나만 보여 줍니다.

### 새로고침과 캐시

| 항목 | 주기 |
|---|---|
| Workers 폴링 | 10초마다 |
| Quotas 폴링과 백엔드 캐시 | 60초마다 |
| 계정별 사용량 조회 | 최대 2분에 한 번 |
| 조회 실패 뒤 대기 | 5분 |
| Claude 계정 이메일 조회 | 최대 하루 한 번(실패 뒤 30분) |
| 외부 호출 제한 시간 | 15초 |

새로고침 버튼은 2분 간격은 건너뛰지만 조회 실패 뒤의 대기는 지키며, 누를 때마다 30초 쉽니다. 사용량 API 는 몰린 요청에 몇 분씩 이어지는 속도 제한으로 답하기 때문입니다.

계정별 조회 간격과 실패 뒤 대기는 풀에 든 계정에만 적용됩니다. DeepSeek 잔액은 쿼터 응답을 다시 만들 때마다 새로 요청합니다. 60초 폴링마다 최대 한 번이고, Quotas 메뉴를 열거나 새로고침할 때마다 한 번씩 더 요청합니다.

## 개인정보와 보안

**워커.** 백엔드는 로컬 Kanban 보드와 워커 세션 데이터베이스를 읽기 전용으로 열고, 그 데이터베이스에 쓰지 않습니다. 다만 SQLite 가 여는 데이터베이스 옆에 자체적으로 빈 `-wal` 보조 파일을 남길 수 있습니다. 데이터베이스 내용은 바뀌지 않습니다. 활동 메타데이터만 돌려줍니다. 메시지 내용과 도구 인자는 Desktop 플러그인에 전달되지 않으며, 인자는 반복 감지를 위한 해시로만 씁니다.

**자격 증명.** 쿼터를 모으기 위해 백엔드는 각 프로필의 자격 증명 저장소(`auth.json`)를 한 번에 한 프로필씩 변경 불가능한 스냅숏으로 읽고, 그 스냅숏으로 사용량 요청만 보냅니다. 쿼터 조회는 자격 증명을 갱신·변경·저장하지 않으며, 한 프로필의 비밀값을 다른 프로필로 옮기지 않습니다. 만료된 토큰은 갱신하지 않고 건너뜁니다. 다만 Hermes 코어 자체는 활성 프로필의 Anthropic 토큰을 만료 직전에, Codex 토큰을 HTTP 401 뒤에 갱신해 그 프로필의 `auth.json` 만 다시 쓸 수 있습니다. 자격 증명은 백엔드에만 머물고 Desktop 플러그인으로 돌아가지 않습니다.

**네트워크.** 백엔드가 호출하는 곳은 다음뿐입니다.

- Hermes 자체가 각 프로바이더에 쓰는 계정 사용량 엔드포인트. 계정마다 그 계정의 토큰으로만 호출합니다.
- `GET https://api.anthropic.com/api/oauth/profile`: Claude OAuth 계정의 이메일을 읽습니다.
- `GET https://api.deepseek.com/user/balance`: DeepSeek 키가 설정된 경우에만 호출합니다.

빌려 쓰는 Claude Code 로그인의 이메일은 Claude Code 자체 설정(`CLAUDE_CONFIG_DIR` 의 `.claude.json`, 없으면 홈 디렉터리)에서 네트워크 호출 없이 읽습니다.

**로컬 파일.** Hermes 홈 아래 소유자 전용 파일 두 개가 재시작 뒤에도 상태를 유지합니다. 같은 홈을 쓰는 백엔드 프로세스들이 함께 쓰며, 파일 잠금 아래에서 쓰기를 합칩니다.

| 파일 | 내용 |
|---|---|
| `cache/hermes-monitor/account-emails.json` | Claude 계정별 이메일 |
| `cache/hermes-monitor/account-usage.json` | 계정별 마지막 정상 조회 값과 마지막 실패 시각. `cached` 대체 표시와 공유 대기에 쓰며, 6시간보다 오래된 항목은 지웁니다. |

저장된 항목마다 그 값을 읽은 토큰의 잘린 SHA-256 을 함께 두고, 토큰 자체는 저장하지 않습니다. 풀 항목이 다른 계정으로 다시 로그인하면 저장된 이메일·조회 값·대기를 버리고 새로 읽습니다. 모든 풀에서 빠진 항목은 모든 풀을 읽는 다음 수집 때 이메일 파일에서 지웁니다.

**UI 로 가는 것.** 토큰, 키, 절대 경로는 Desktop 플러그인으로 보내지 않습니다. Desktop 플러그인이 받아 메뉴에 보여 주는 것은 다음과 같습니다.

- 실행 중인 카드의 제목, 카드 id, 담당자(Kanban 보드에 적힌 그대로)
- 각 계정이 속한 Hermes 프로필 이름, DeepSeek 의 경우 키를 읽은 곳의 이름(`env`, `root` 또는 프로필 이름)
- Claude 계정의 로그인 이메일

이 값들은 내 컴퓨터 안에만 머물고, 플러그인이 다른 곳으로 보내지 않습니다.

## 문제 해결

**상태바 항목이 보이지 않습니다.** 플러그인이 켜져 있는지(`hermes plugins list`), Capabilities -> Plugins -> Hermes Monitor 에서 Desktop 쪽 스위치가 켜져 있는지 확인한 뒤 Hermes Desktop 을 종료했다가 다시 엽니다.

**Workers 가 `n/a` 입니다.** 백엔드가 Kanban 보드(Hermes 홈의 `kanban.db`)를 읽지 못했습니다. 예를 들어 아직 보드가 없는 경우입니다.

**Quotas 에 프로바이더가 없습니다.** 어느 프로필에도 자격 증명이 없거나, Hermes 에 그 프로바이더의 사용량 조회 기능이 없습니다.

**계정이 `cached` 입니다.** 마지막 사용량 조회가 실패했습니다. 대개 벤더의 속도 제한 때문입니다. 마지막 정상 값을 최대 6시간 보여 주고, 5분 대기 뒤 다시 읽습니다.

## 개발

필요한 것: `pytest` 와 `fastapi` 가 있는 Python 3.11 이상, 문법 검사용 Node.js. 테스트는 fixture 만 쓰고 네트워크를 호출하지 않습니다.

```sh
python3 -m pytest tests -q
node --check desktop/plugin.js
```

테스트는 저장소 루트에서 실행합니다.

| 경로 | 역할 |
|---|---|
| `dashboard/plugin_api.py` | 백엔드 경로(`/workers`, `/quotas`)와 데이터 수집 |
| `dashboard/workers.py`, `dashboard/quotas.py` | 응답 데이터로 바꾸는 순수 변환 |
| `desktop/plugin.js` | Desktop 쪽: 상태바 항목과 메뉴 |
